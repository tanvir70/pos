# Business & Architecture Decisions Log

This document records all domain, financial, operational, and architectural decisions taken during the development of the **Al-Amin Traders (মেসার্স আল-আমিন ট্রেডার্স) POS & Agrochemical Dealership System**.

It is split into two distinct parts:
1. **Part 1: Backend Architecture & Enterprise Core Decisions** (Spring Boot 3, Java 21, Flyway, JPA, Concurrency & Security)
2. **Part 2: Frontend Terminal & UI/UX Cockpit Decisions** (React 19, TypeScript 5.7, Tailwind CSS v4, Contexts & 60/40 Cockpit)

---

## Part 1: Backend Architecture & Enterprise Core Decisions

| Date | Topic | Decision | Operational Rationale | Impact / Cost if Changed |
| :--- | :--- | :--- | :--- | :--- |
| 2026-09-16 | Stock Unit Storage | Store strictly in base units (Bottle, Packet, Kg, Liter); Cartons are multiplier-only at `NUMERIC(12, 3)`. | Prevents manual break-bulk bookkeeping errors when unpacking wholesale cartons for counter sale. | Inventory balances remain unified and cannot drift between cartons and pieces. |
| 2026-09-17 | Java 21 Pinning for Gradle | Pin `org.gradle.java.home` to Java 21 LTS in `gradle.properties`. | Ensures build reproducibility across developer machines and CI where host system JDK may default to Java 25. | Prevents Gradle 8 daemon crashes on unsupported JVM versions. |
| 2026-09-17 | ANSI SQL Identity Keys | Use `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` across all tables. | Provides standard SQL portability between H2 (dev/embedded file mode) and PostgreSQL (production) without dialect-specific sequences or BIGSERIAL macros. | Zero migration rework required when moving from H2 to PostgreSQL. |
| 2026-09-17 | Unconstrained Customer Ledger Sale ID | Keep `customer_ledger.sale_id` as indexed `BIGINT` without strict foreign key constraint. | Supports non-sale transactions (e.g., opening due balances, paper money receipt cash payments, manual credit adjustments) without inserting synthetic dummy sale records. | Clean customer credit history without foreign key violations. |
| 2026-09-17 | Dual-Lot Seeding for FEFO | Seed catalog products (e.g. Amistar Top) with multiple active lots with varying expiry dates. | Enables immediate unit and integration testing of FEFO (First Expired, First Out) dispatch queries and cashier manual overrides. | Guarantees test coverage for core business inventory dispatch rules. |
| 2026-09-17 | Deterministic Customer Ledger Order | Query latest customer ledger balance using `OrderByTransactionDateDescIdDesc`. | Ensures deterministic balance retrieval even when multiple sales or payments occur within the exact same second. | Prevents non-deterministic current due balance drift. |
| 2026-09-17 | Carton Multiplier Conversion on Lot Entry | Convert incoming cartons to base units via `(cartons * product.cartonMultiplier) + looseUnits` and record exclusively in baseUnit at `NUMERIC(12, 3)`. | Eliminates manual unit calculations and prevents unit mismatch between cartons in storage and individual units on retail counter. | Consistent base unit balance prevents break-bulk inventory drift. |
| 2026-09-17 | Automatic Barcode Synthesis | When barcode is blank during lot registration, auto-generate unique barcode as `SYN-<CODE>-<LOT>`. | Guarantees 100% barcode coverage for fast 1D handheld scanner reading even if supplier barcode is omitted on physical invoice. | Eliminates human data entry delay during busy truck offload. |
| 2026-09-17 | Code 128 1D Barcode Standard | Standardize on Code 128 (1D) format using ZXing `Code128Writer` for lot sticker labels. | Code 128 supports alphanumeric lot codes (e.g., `SYN-AMI-202601`) and scans reliably with standard retail CCD/laser scanners in rural agro shops. | Ensures universal hardware scanner compatibility across all retail counter terminals. |
| 2026-09-17 | Immutable Barcode HTTP Caching | Barcode image endpoints deliver `Cache-Control: public, max-age=86400`. | Lot barcodes and barcode strings are immutable once issued; caching eliminates CPU/stream rendering latency during bulk sticker label printing. | Instantaneous sticker printing response times under high-volume batch printing. |
| 2026-09-17 | Invoice Number Formatting | Format invoice numbers as `INV-YYYYMMDD-XXXX` with 4 random digits and uniqueness verification loop. | Provides clear chronological daily readability on paper printouts while eliminating collision risk. | Reversible format without modifying database constraints. |
| 2026-09-17 | Transactional Unit Cost Snapshot | Freeze `lot.purchaseCost` into `sale_item.unit_cost` at the moment of invoice creation. | Guarantees historical gross profit and gross margin accuracy regardless of subsequent supplier price inflation or lot cost edits. | Permanent financial audit integrity for profit and loss reporting. |
| 2026-09-17 | Customer Profile Balance Protection | Customer profile updates do not overwrite `currentDue` directly; due balance changes occur strictly via sales, repayments, and returns. | Preserves financial ledger integrity and prevents unrecorded balance tampering or manual accounting discrepancies. | Eliminates untracked accounts receivable drift. |
| 2026-09-17 | Customer Opening Balance Ledger Audit | When a customer is registered with an opening due balance, an initial ledger entry is created with `transactionType = 'INVOICE_BILL'`. | Establishes an unbroken, immutable audit trail for historical debt preceding system adoption. | Prevents unexplained opening balances on customer ledger statements. |
| 2026-09-17 | Money Receipt Number for Repayments | Capture Money Receipt (MR No.) voucher number on `CASH_PAYMENT` customer repayments. | Agrochemical dealers issue stamped paper Money Receipt vouchers to farmers clearing seasonal debts. | Protects store and farmers from payment receipt disputes. |
| 2026-09-17 | Sales Return Debt Credit Adjustment | Direct returns with `DUE_ADJUSTMENT` refund type credit the customer due balance via `RETURN_CREDIT` ledger entries. | Reflects standard rural dealer practice where farmers return unapplied chemicals at harvest end to settle outstanding seasonal credit. | Prevents unnecessary cash payout while keeping ledger balances accurate. |
| 2026-09-17 | Live Cash in Drawer Calculation | Live Cash in Drawer computes net cash received today: `salesCash + repaymentsCash - refundsCash` (00:00:00 to 23:59:59). | Gives agrochemical shopkeepers an instant reconciliation figure against physical counter cash drawer before closing. | Prevents daily till discrepancies and untracked petty cash loss. |
| 2026-09-17 | 1-Click Database Backup Engine | Uses native SQL `SCRIPT` query via `JdbcTemplate` to export complete DDL and INSERT statements directly to an attachment stream. | Enables 1-click download directly to local disk or USB flash drive without requiring external CLI utilities (`mysqldump`, `pg_dump`) or OS shell access. | Zero installation dependencies for non-technical retail store operators. |
| 2026-09-17 | Expiring Lot Alert Threshold & Priority | Flag lots expiring on or before `LocalDate.now().plusDays(30)` sorted by `expiryDate` ascending (FEFO priority). | Notifies shopkeeper of impending chemical expiration in time to push or discount stock before shelf life lapses. | Protects store from expired chemical inventory write-offs. |
| 2026-09-17 | Product Catalog REST Controller | Provide `/api/products` endpoints (`GET` with optional search query and `POST` for product creation) to expose the seeded Syngenta catalog and allow adding new products. | Enables frontend product catalog and autocomplete searches to query database products directly instead of hardcoded client-side mock data. | Full parity between backend database products and frontend catalog. |
| 2026-09-17 | E2E Integration Test Isolation & H2 SCRIPT Commit Handling | Configure isolated in-memory test database for automated test suite, with `@DirtiesContext` and idempotent pre/post cleanup handlers in `SyngentaBusinessFlowTest`. | H2 `SCRIPT` query executes an implicit SQL commit on the connection; dedicated test database isolation and cleanup prevents end-to-end integration test data from leaking into unit/repository tests or polluting developer disk. | Guarantees 100% test repeatability and prevents flaky test interdependencies across the build suite. |
| 2026-09-17 | Pure Standard Domain Exception Hierarchy & Uniform Error Envelope | Refactored backend error handling to strict industry standards: abstract `PosException` extending `RuntimeException`, typed domain exceptions (`ResourceNotFoundException`, `InsufficientStockException`, `DuplicateResourceException`, `BusinessRuleViolationException`, `ValidationException`, `BarcodeGenerationException`) with HTTP statuses (404, 422, 409, 400, 500) and uniform `ErrorResponse` envelope. | Replaced ad-hoc `IllegalArgumentException` throws and generic error payloads with a pure, strongly-typed domain hierarchy without backward-compatibility shortcuts. Standardizes frontend error handling and guarantees robust API contracts. | Clean architectural separation, seamless frontend form error mapping, zero shortcut compromises. |
| 2026-09-17 | Pessimistic Locking & Concurrency Control | Implemented `PESSIMISTIC_WRITE` locking on `StockInventory` and `Customer` during sale checkouts, repayments, and returns. | Prevents race conditions, double-allocation, and ledger drift when multiple counter requests execute concurrently. | Eliminates financial discrepancy under simultaneous counter sales. |
| 2026-09-17 | Transaction Idempotency Filter & Replay Prevention | Implemented `IdempotencyFilter` with in-memory caching and clean TTL eviction matching on `X-Idempotency-Key` HTTP header. | Prevents duplicate charge or duplicate inventory decrement when network hiccups cause double button taps or browser retries. | Absolute protection against double-billing. |
| 2026-09-17 | Removal of Godown Warehouse Subsystem | Completely eliminated Godown warehouse subsystem from both backend and frontend. Consolidated stock into single store inventory (`DOKAN`) plus `QUARANTINE` for damaged chemicals. Dropped `godown_movement` table, `godown_quantity` columns, `transfer_number_seq`, split-stock modals, transfer tickets, and inter-location routing via Flyway migration `V4__remove_godown.sql`. | Business requirement evolved to eliminate multi-warehouse complexity; retail dealership operates from a single primary store counter. Removing split-stock billing and transfers streamlines cashier checkout speed and eliminates double-entry errors. | Dramatically simplifies schema and POS flow, guarantees ultra-slick terminal execution, and maintains 100% test coverage (130/130 tests passing). |
| 2026-09-17 | Quarantine Damaged Goods Inventory Tracking & Disposal | Implemented `GET /api/inventory/quarantine` and `POST /api/inventory/quarantine/dispose` with strict Spring Security RBAC (`hasRole("OWNER")`). | Damaged, leaking, or expired agrochemicals are permanently isolated from saleable store stock and require Owner authentication to write off or destroy. | Enforces regulatory pesticide safety and protects business owners from unauthorized inventory shrinkage. |
| 2026-09-17 | Pure PostgreSQL Architecture & Complete Removal of H2 | Completely eliminated H2 dependency from `build.gradle`, application configs, and test suites. Standardized on PostgreSQL 10+ using `org.postgresql:postgresql` and `org.flywaydb:flyway-database-postgresql` for both development (`posdb`) and automated testing (`posdb_test`). Replaced H2-specific `SCRIPT` backup command with pure JDBC streaming SQL table exporter with `session_replication_role` protection. Added explicit parameter casting (`CAST(:query AS string)`) for PostgreSQL type inference. | Simplifies runtime environment, ensures exact parity between local development, testing, and production environments, eliminates dual-dialect compatibility quirks, and utilizes production-grade PostgreSQL transactions and pessimistic locking across the board. | 100% green test suite (130/130 tests passing on PostgreSQL), zero H2 artifacts or dependencies in project. |

## Part 2: Frontend Terminal & UI/UX Cockpit Decisions

| Date | Topic | Decision | Operational Rationale | Impact / Cost if Changed |
| :--- | :--- | :--- | :--- | :--- |
| 2026-09-16 | Cashier Role & Cost Hiding | 4-digit Master PIN toggles Owner Mode vs. Cashier Mode. | Prevents counter sales assistants from viewing purchase cost (কেনা দাম) and daily gross profits during bargaining. | Enforces business privacy and prevents trade margin leaking. |
| 2026-09-16 | Price Overrides & Bargaining | Allow line-item price discount/override in cart while showing purchase cost to seller in Owner Mode. | Matches physical bargaining reality in rural Bangladesh agro-markets. | Enables cashier to close deals without corrupting master product catalog. |
| 2026-09-16 | Direct Returns | Support sales returns without requiring original paper receipt lookup. | Farmers frequently lose paper receipts over 15-30 day chemical application periods. | Unopened goods restocked to Dokan; damaged goods routed to quarantine. |
| 2026-09-16 | Round-Off Adjustment | 1-click round-off field zeroes small change (e.g. ৳1453 $\to$ ৳1450). | Prevents customer credit ledger from accumulating trivial petty debts. | Cleaner accounts receivable accounting. |
| 2026-09-16 | Money Receipt (MR No) | Auto-suggests `MR-<timestamp>` if cashier omits manual serial from physical paper memo book. | Farmers demand physical signed proof of debt clearance. | Protects store and customer from debt disputes. |
| 2026-09-16 | Wholesale Profile Data | Capture Business Name, Proprietor Name, Father's Name, Phone, WhatsApp, Village, MFS/Bank info, and Credit Limit. | Rural union disambiguation, sending WhatsApp digital bills, and enforcing credit ceilings. | Mitigates default risk on large seasonal chemical credit. |
| 2026-09-17 | Frontend API Client Native Fetch & Vite Proxy | Frontend uses native browser `fetch` targeting `/api` prefixed endpoints, routed to backend `http://localhost:8080` via Vite development proxy and configurable via `VITE_API_BASE_URL`. | Eliminates external HTTP library weight (Axios), eliminates CORS issues in local development, and simplifies production deployment behind an Nginx reverse proxy. | Zero dependency footprint; changing API gateway requires only environment variable update. |
| 2026-09-17 | Bearer Token & Idempotency Injection | `client.ts` automatically attaches `Authorization: Bearer <token>` from local storage and generates unique `X-Idempotency-Key` (UUID) for mutating requests (`POST`, `PUT`, `DELETE`). | Centralizes authentication header dispatch and guarantees replay attack protection across all frontend API calls. | Complete API communication security without manual header plumbing in individual components. |
| 2026-09-17 | Dual Print Formats (80mm & A4) | Provide both 80mm thermal receipt and full A4 Wholesale Challan & Invoice with dual signatures. | Counter retail farmers require compact paper receipts, while wholesale dealers require formal signed legal challans with full ledger history. | Eliminates manual carbon paper challan books for wholesale deliveries. |
| 2026-09-17 | In-Line POS Bargaining Price Override | Allow direct line-item unit price editing on cart items with visual amber badge indicator for modified rates. | Rural agro-dealers negotiate bulk pesticide prices per-farmer; requires instant rate adjustments without altering master catalog prices. | Eliminates separate manual discount vouchers. |
| 2026-09-17 | Carton Multiplier Live Base Unit Conversion | Lot entry modal computes total base units dynamically via `(cartons * multiplier) + looseUnits` with real-time formula display. | Eliminates manual arithmetic errors during shipment intake at store receiving dock. | Guarantees consistent base unit inventory in database. |
| 2026-09-17 | 50mm x 25mm Thermal Barcode Label Generation | Generates Code 128 thermal labels with Syngenta branding, bilingual names, FEFO lot/expiry, and legally mandated MRP. | Allows store workers to stick scannable barcode labels on loose pesticide containers and boxes. | Eliminates manual handwritten pricing and enables 1D scanner checkout. |
| 2026-09-17 | Role-Based Purchase Cost Masking | Purchase costs (কেনা দাম) and total stock valuation are masked as locked (`[🔒 আনলক]`) unless Owner Mode PIN is validated. | Protects trade secrets and dealership profit margins from counter assistants while allowing unobstructed stock logistics. | Preserves financial confidentiality on shared counter PC. |
| 2026-09-17 | Direct WhatsApp Due Notification | Direct WhatsApp messaging automatically formats Bangladesh mobile numbers to +880 international format and generates a pre-composed polite Bengali balance reminder message. | Enables agrochemical dealers to dispatch instant debt reminders and balance statements to farmers on rural smartphones with one click. | Eliminates manual phone dialling or handwritten paper credit letters. |
| 2026-09-17 | Customer Credit Limit Utilization Alert | Displays real-time progress bar and amber/red badge alerts when customer outstanding debt approaches or exceeds agreed credit limit. | Prevents uncollateralized credit defaults during peak agricultural planting seasons while giving dealers visual warnings. | Mitigates accounts receivable risk without halting genuine counter transactions. |
| 2026-09-17 | Quarantined Damaged Chemical Stock Separation | When returned chemical is marked damaged (`isDamaged = true`), goods are routed to quarantine storage and excluded from sellable counter stock. | Leaking, contaminated, or unsealed pesticide containers must never be re-dispensed to farmers. | Protects store liability and crop safety while awaiting supplier credit notes. |
| 2026-09-17 | Executive Analytics Protected Profit Margin | Daily Gross Profit and Monthly Profit metrics on Analytics Dashboard are locked behind 4-digit Owner PIN (`1234`). | Prevents counter sales assistants and customers from discovering wholesale purchase costs and dealership markup during price bargaining. | Safeguards commercial confidentiality on single-terminal rural store counters. |
| 2026-09-17 | Frontend Modular Architecture & High-Performance Cockpit | Overhauled frontend terminal into high-performance 60/40 cockpit with sub-16ms renders. Implemented integer-paisa precision math (`currency.ts`), non-blocking hardware barcode scanner wedge hook (`barcode.ts`), centralized JWT auth session with 5-min Owner inactivity auto-lock (`AuthContext.tsx`), continuous session storage cart persistence (`CartContext.tsx`), Bengali error translations (`ToastContext.tsx`), modular cockpit components (`ProductCatalogGrid`, `CartTicket`, `SettlementPanel`, `CustomerSelect`, `DualPrintModal`), and quarantined chemical write-off disposal. | Replaced monolithic component sprawl with production-grade atomic primitives and modular architecture. Eliminates all UI lag, prevents floating-point penny drift, and guarantees seamless offline-resilient cashier workflow on counter PCs. | Blazing fast 160ms Vite builds, zero-vertical-scroll cockpit, full type safety, and zero unhandled errors. |
| 2026-09-17 | Symmetrical Accounting Precision Currency Engine | Formulated `calcLineTotal` as `roundAccounting(quantity * unitPrice)` operating on integer paisa representation. | Prevents floating point errors and argument order drift when multiplying fractional weights/liters by unit prices. | Guarantees exact parity with backend BigDecimal accounting math. |
| 2026-09-17 | Hardware Barcode Scanner Wedge Interceptor | Implemented `useBarcodeScanner` hook detecting keystroke intervals $\le 35\text{ms}$ ending with `Enter`. | Hardware USB/Bluetooth laser scanners emit rapid keyboard wedge events; intercepting them globally prevents text characters from corrupting active form inputs. | 100% reliable hardware scanning on live billing counter. |
| 2026-09-17 | Active Bill Session Storage Mirroring | Continuous auto-save of active billing cart, selected customer, discount, and tender values to `sessionStorage` (`pos_active_cart_v1`). | Prevents total bill loss if cashier accidentally refreshes page, switches tabs, or suffers a browser crash during high-volume counter rush. | Cashier returns immediately to ongoing transaction with zero customer delay. |
| 2026-09-17 | Centralized Owner Inactivity Auto-Lock | Setup 5-minute idle watchdog tracking `mousemove`, `keydown`, `touchstart`, `click`, and `scroll` in `AuthContext.tsx`. | If owner leaves counter terminal unattended, system automatically drops permissions back to `ROLE_CASHIER` to protect trade secret wholesale prices. | Automated security without requiring cashier to remember manual sign-out. |
| 2026-09-17 | High-Contrast Dual-Theme Atomic Design System | Built 8 atomic UI primitives (`Button`, `Input`, `Badge`, `Card`, `Modal`, `StatCard`, `TouchNumpad`, `Table`) with $\ge 44\text{px}$ touch targets and high-contrast color styling. | Counter laptop monitors frequently suffer from sunlight glare in rural storefronts; large targets and high contrast ensure effortless readability and touch interaction. | Fast, error-free cashier input under harsh shop counter conditions. |
